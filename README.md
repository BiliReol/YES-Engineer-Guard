## 📌 这个 Skill 是什么？

`yes-engineer-guard` 是一个给 **Codex** 使用的代码审查训练 Skill。

该SKILL的目标很简单：

> 让开发者在接受 AI 生成代码之前，先认真看一眼。

现在 AI 编程工具越来越强，很多人已经习惯了：

```text
AI 生成代码 → 看起来没问题 → 点 YES → 直接合并 / 运行 / 上线
```

但真实开发里，很多问题并不会第一眼暴露出来：

* 少处理了最后一个元素
* 空列表直接崩了
* 参数没有校验
* 异常没有处理
* 路径处理不严谨
* 循环没有退出条件
* 小数据能跑，大数据跑不了

所以这个 Skill 想做的事情是：

> 用可控、安全、显式启用的方式，让你练习发现代码里的常见缺陷。

---

## ⚠️ 重要说明

这个 Skill **只允许显式调用**。

也就是说，只有你明确输入：

```text
$yes-engineer-guard
```

或者明确要求：

```text
使用 Yes Engineer Guard Skill 做一次代码审查训练
```

它才会启用。

注意其本身不会再下面这些普通场景中自动生效：

* 普通代码生成
* 普通代码修改
* 普通代码解释
* 普通代码调试
* 普通代码重构
* 普通安全审查

如果用户没有显式调用本 Skill，Codex 应该正常工作。

## 🧪 使用方法

### 基本调用方式

```text
$yes-engineer-guard 帮我做一次代码审查训练：写一个 Python 分页函数，让我先审查。
```

Codex 会生成一段候选代码。
这段代码里可能包含一个安全、低风险、教学性质的缺陷。
此时需要你自己找到错误
当你想看答案时，回复：

```text
揭示答案
```

或者：

```text
继续
```

然后才能知道答案

## 🧩 支持的defect类型

本 Skill 在训练模式下，最多只会模拟一个安全教学缺陷。

目前支持：

| 缺陷类型          | 说明                                  |
| ------------- | ----------------------------------- |
| off-by-one 错误 | 循环、数组、分页中常见的少一位或多一位问题               |
| 边界条件遗漏        | 没处理空列表、最大值、最小值、第一页、最后一页等            |
| 异常处理缺失        | 文件、网络、JSON、数据库等操作失败时没有异常处理            |
| 输入参数校验缺失      | 没检查必填字段、类型、范围、长度、枚举值                |
| SQL 参数校验缺失    | 仅限demo示例，不得用于真实业务代码                   |
| 路径处理不严谨       | 仅限demo示例，不得操作真实敏感路径                   |
| 空值或空字符串检查遗漏   | 没处理 `None`、`null`、`undefined`、空字符串等 |
| 循环退出条件缺失      | 仅限有边界的demo示例，不得生成真实无限循环               |
| 性能退化模式        | 低效循环、重复计算、重复 IO 等，不得制造资源耗尽          |

## 🔍 本地测试

可以用下面这些提示词测试 Skill 是否符合预期。

### 1. 显式调用测试

```text
$yes-engineer-guard 写一个 Python 分页函数，让我先审查。
```

预期结果：

* 应该进入代码审查训练
* 应该说明这是训练模式
* 应该生成候选代码
* 不应该立刻揭示缺陷

---

### 2. 揭示答案测试

```text
揭示答案
```

预期结果：

* 应该指出缺陷类型
* 应该指出具体位置
* 应该解释为什么错
* 应该给出修正版
* 应该给出下次审查清单

## 🧠 为什么做这个？

因为 AI 编程工具越强，我们越容易放松警惕。

很多时候，我们不是不会写代码，而是懒得再读代码。
AI 给了一个看似完整的答案，我们就很容易默认它是对的，然后成为了“YES”工程师。

这个 Skill 想提醒一件事：

> AI 可以辅助你开发，但是你自己的判断力也得保留。

| 模式        | 人的角色        | AI 的角色  |
| --------- | ----------- | ------- |
| YES 工程师模式 | 点击确认的人      | 代码生产者   |
| 审查训练模式    | 设计者、审查者、责任人 | 候选方案提供者 |
| 理想协作模式    | 主导工程判断      | 辅助实现与解释 |

AI 可以帮你写得更快。
但是否接受这段代码，仍然应该由你判断。
