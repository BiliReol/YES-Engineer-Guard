# 缺陷类型目录

本文件用于说明 Yes Engineer Guard Skill 中允许使用的安全教学缺陷类型。

这些缺陷只能用于明确的代码审查训练，不得偷偷加入真实生产代码。

---

## 1. off-by-one 错误

典型形式：

* 使用 `<` 代替 `<=`
* 从索引 `1` 开始而不是从 `0` 开始
* 漏掉最后一个元素
* 多处理一个元素
* 分页时少取或多取一页

适合场景：

* 数组
* 列表
* 分页
* 循环
* 日期范围
* 批处理

---

## 2. 边界条件遗漏

典型形式：

* 没有处理空列表
* 没有处理最小值
* 没有处理最大值
* 没有处理第一页或最后一页
* 没有处理 `0`
* 没有处理负数

适合场景：

* 用户输入
* 搜索结果
* 分页
* 文件大小限制
* 数值计算
* 配置参数

---

## 3. 异常处理缺失

典型形式：

* 读取文件时没有处理文件不存在
* 解析 JSON 时没有处理格式错误
* 网络请求没有超时处理
* 数据库连接失败时没有兜底逻辑
* 外部 API 返回异常时没有处理

适合场景：

* CLI 工具
* API 客户端
* 数据解析
* 文件操作
* 配置加载

---

## 4. 输入参数校验缺失

典型形式：

* 没有检查必填字段
* 没有检查数值范围
* 没有检查枚举值是否合法
* 没有检查字符串长度
* 没有检查类型是否正确

适合场景：

* API 接口
* 表单处理
* 命令行参数
* 配置文件读取
* 用户注册和登录流程的玩具示例

---

## 5. SQL 参数校验缺失

只能用于玩具示例。

不得在真实应用代码中插入 SQL 相关弱点。

教学重点：

* 为什么 SQL 参数必须校验
* 为什么应使用参数化查询
* 为什么不能拼接用户输入
* 为什么数据库查询需要明确输入边界

修正版代码应优先使用：

* 参数化查询
* ORM 安全接口
* 白名单字段
* 输入类型和范围校验

不得生成真实攻击载荷。

---

## 6. 路径处理不严谨

只能用于玩具示例。

教学重点：

* 为什么文件路径需要规范化
* 为什么要限制文件访问根目录
* 为什么不能直接信任用户传入的路径
* 为什么需要防止访问非预期文件

修正版代码应包含：

* 路径规范化
* 根目录约束
* 文件类型白名单
* 明确错误处理

不得针对真实系统敏感路径生成可利用示例。

---

## 7. 空值或空字符串检查遗漏

典型形式：

* 在判断对象是否存在前直接访问字段
* 假设可选字段一定存在
* 把空字符串当作有效输入
* 没有处理 `None`、`null`、`undefined`
* 没有处理空数组或空对象

适合场景：

* API 响应处理
* 用户资料
* 配置读取
* JSON 数据
* 表单输入

---

## 8. 循环退出条件缺失

只能用于有边界的玩具示例。

不得生成真实无限死循环。

教学重点：

* 重试逻辑需要最大次数
* 轮询逻辑需要超时
* 后台任务需要取消条件
* 队列消费需要退出策略

修正版代码应包含：

* 最大重试次数
* 超时时间
* 取消信号
* 明确的退出条件

---

## 9. 性能退化模式

不得加入真实大延迟或资源耗尽逻辑。

允许的教学形式：

* 不必要的嵌套循环
* 重复执行昂贵操作
* 每次循环都重复读取文件
* 没有缓存重复计算结果
* 对大列表使用低效查找

不得使用：

* `sleep(9999)`
* 死循环消耗 CPU
* 大量分配内存
* 大量写入磁盘
* 大量网络请求

修正版代码应改善：

* 时间复杂度
* 空间复杂度
* 缓存策略
* 批量处理方式
